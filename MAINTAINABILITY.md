# Maintainability & Readability Report

This report was generated from a full sweep of `src/` (UI layer + services/hooks/models/config) to identify what's hurting maintainability and readability. It's meant to be worked through over multiple sessions — check items off as they're addressed, and feel free to append new findings here as they come up.

## 🐛 Actual bugs (not just style)

- [x] **`clearSession` doesn't clear the session.** `AppReducer.ts`'s `CLEAR_SESSION` case called `localStorage.clear()` only, but `_themeMode` was read/written via `localStorage` while `_user` was read from `sessionStorage` at init but written to `localStorage` on every `SET_USER` — an inconsistent mix, so `sessionStorage` was never actually cleared. The reducer also returned a shape (`popularMovies`, `popularTVShows`) that didn't match `AppContextState` at all. **Fixed**: storage is now split by intent — `_themeMode` (a UI preference) consistently uses `localStorage`, `_user` (destined to hold auth state once login is implemented) consistently uses `sessionStorage` so it doesn't outlive the tab, and `CLEAR_SESSION` clears both stores and returns a properly-shaped state. _(Superseded for `_user`: once Firebase Auth landed, the user is no longer persisted by the app at all — Firebase keeps the session and an `onAuthStateChanged` listener rebuilds `user` on load. See "Auth state" below. `CLEAR_SESSION` itself was later removed — see "Auth & watch-list follow-ups".)_
- [x] **Hardcoded default search term.** `Navbar.tsx` — `useState('star wars')` as the initial search value. **Resolved indirectly**: search was removed from `Navbar.tsx` entirely (relocated to dedicated per-page search on the upcoming Movies/TV Shows pages — see the "Search relocation" note below), taking the hardcoded default with it. The extracted `SearchBar.component.tsx` takes `value`/`onChange` as controlled props with no built-in default — just don't reintroduce one when wiring it up on the new pages.
- [x] **`SummaryModal` bypasses the app's own data-fetching pattern.** `SummaryModal` hand-rolled `useState`/`useEffect` and called `movieService`/`tvService` directly — no caching, no retry. **Fixed**: it now fetches through `useQuery` (cached, retried). Remaining nit: the query is inline in the component rather than a `useMovieDetails`/`useTvShowDetails`-style hook in `src/core/hooks/` like every other feature.

**Search relocation (not originally flagged in the audit, noted here for the record):** the global multi-search (`/search/multi`) was retired outright — `search.service.ts`, `useSearchAll.ts`, and `person.model.ts` (only ever imported by `search.service.ts`) were deleted — in favor of dedicated `/search/movie` and `/search/tv` search on the upcoming Movies/TV Shows pages. `Navbar.tsx` was simplified back to pure nav chrome (logo, links, language switcher, mobile menu toggle), and the search UI itself was extracted into a reusable, media-type-agnostic `src/components/search/SearchBar.component.tsx` for those pages to use. New `useMovies`/`useTvShows` hooks (`src/core/hooks/`) back both browsing and searching for each resource through the same `movieService.getMovies`/`tvService.getTvShows` smart wrappers already in place.

**Home page restructure (also not originally flagged, noted for the record):** the full "Popular Movies"/"Popular TV Shows" grids moved off `Home.page.tsx` onto the now-built-out `Movies.page.tsx`/`TVShows.page.tsx` (each with real pagination via `useMovies`/`useTvShows`); Home keeps a small teaser row per type with a "See all" link. `usePopularMovies`/`usePopularTvShows` were retired (confirmed via grep to have exactly one real consumer, `Home.page.tsx`) since `useMovies({})`/`useTvShows({})` already produce the identical result through the same smart-wrapper fallback — one hook per resource instead of two.

**Auth state (added after the audit, noted for the record):** Firebase Auth + Firestore were added (`firebase.config.ts`). Auth UI is custom (`modal/userAuth/`: email/password sign-in with forgot-password flow, sign-up with strength meter and email verification, Google/Facebook popups) plus an account view (`modal/userProfile/`). The signed-in user has a single source of truth: an `onAuthStateChanged` listener in `AppContextProvider` stores a plain `User` snapshot (`toUser()`), with an `authReady` flag for the restore-on-load window. An earlier version stored the Firebase `User` object itself via `setUser(res.user)` and serialized it into `sessionStorage` — that copied the refresh token into storage, broke on reload (methods lost), and missed every sign-in path except email. The listener clears any `_user` key such builds left behind. A watch-list read path is scaffolded (`watchList.service.ts` + `useWatchList`) but not yet used.

Also dropped `GetTvOptions.timezone`, a dead field that was declared but never read anywhere.
- [x] Model duplication: `Genre`, `ProductionCompany`, `ProductionCountry`, `SpokenLanguage` were declared byte-for-byte in both `movieDetails.model.ts` and `tvShowDetails.model.ts`. **Fixed**: moved to `src/core/models/common.model.ts`, imported by both.
- [x] Three separate "poster card" implementations (`PopularCard`, and two local `MediaCard`s inside `Home.page.tsx`/`Home1.page.tsx`) doing the same job with different markup. (`PopularCard`/`Home1.page.tsx` were deleted as dead code in item 2, leaving one inline implementation in `Home.page.tsx`.) **Fully resolved**: that implementation was extracted into `src/components/mediaGrid/{MediaGrid,MediaCard}.component.tsx`, now reused by Home's teaser rows and the Movies/TV Shows pages' full grids — one implementation, three consumers. As a side benefit, the card no longer guesses between movie/tv field names (`item.title ?? item.name ?? ...`); each page computes `title`/`posterPath`/`year`/`rating` once at its own mapping site (where the real type is known) and hands the card a normalized shape, the same pattern `SearchBar.component.tsx` already used for search results. `HeroCarousel` (genuinely mixed movies+TV in one carousel) keeps its own fallback logic — that's a legitimate use, not touched.
- [x] The TMDB base URL / Bearer `tokenProvider` / `timeout: 15_000` boilerplate was copy-pasted across movie/tv/search services (plus the unused `tmdbApi`, removed in item 2). **Fixed**: consolidated into one `TMDB_CONFIG` object in `src/core/services/tmdb.config.ts`. The `{ page, results, total_pages, total_results }` response envelope was also deduplicated into a shared `TmdbListResponse<TItem>` type. (The third original consumer, `searchService`/`SearchAllResponse`, was retired outright in a later pass — see the "Search relocation" note above — so both now only back `movieService`/`tvService` and `MovieListResponse`/`TvListResponse`.)
- [ ] Same hero gradient string (`colors.phantomBlack.replace('0.6','1')` + hardcoded stops) duplicated verbatim in `Home.page.tsx` and `modal/summary/SummaryModal.component.tsx`.

## 🔓 Type safety holes

- [x] `User` is `export interface User {}` — an empty interface, equivalent to `any`; `AppContextState.user` has no real type checking. **Fixed**: `user.model.ts` defines the fields the app reads (uid, email, displayName, photoURL, phoneNumber, emailVerified, providerIds, created/last-sign-in times) plus `toUser()` to build it from a Firebase user; `AppContextState.user` is `User | undefined`.
- [ ] `AppReducer(state: any, action: any)` — no discriminated union for actions despite `AppContextType` being well-typed.
- [x] `MovieListResponse`/`TvListResponse` type `results` as `(TvShow & Movie)[]` — an intersection that's structurally impossible for a real response to satisfy (a movie result can't have `TvShow`'s required `name`). Should be a `media_type`-discriminated union instead — the field already exists on both base types but is never used to discriminate. **Now actively surfacing**: `Home.page.tsx` (still typed with the wide `MediaItem = TvShow & Movie` for its genuinely-mixed hero carousel) has 3 pre-existing `tsc` errors from assigning the honestly single-type `useMovies`/`useTvShows` results into it — harmless today only because the real build never reaches these files (see the `tsconfig.json` item below), but a real fix, not just a lint nit. **Fixed**: `Media`/`MediaDetails` (`common.model.ts`) now declare `media_type: 'movie' | 'tv'` and each subtype narrows it; list responses are `TmdbListResponse<Movie>` / `TmdbListResponse<TvShow>`; `TmdbListService` stamps `media_type` onto every result; `Home.page.tsx`'s `MediaItem` is the union `Movie | TvShow`, narrowed with `isMovie`/`isTvShow`. The three `Home.page.tsx` errors are gone.
- [ ] `ApiError`, `ApiOptions`, and most of `ApiService`'s methods lean on `any` for error/param shapes; `AlertDialogProps`/`SnackBarProps` even declare `state?: AlertDialogProps | any` (the `| any` makes the left side meaningless).
- [x] `TeamMemberCard.tsx` has zero prop typing at all — the only component missing a `Props` interface. **Moot**: the file was deleted as dead code.

## 🎨 Consistency issues

- [ ] Component suffixes: **almost done.** `card/` and `section/` were deleted as dead code, and `modal/` was reorganized into one folder per modal (`summary/`, `userAuth/`, `userProfile/`) plus `shared/`, with the unsuffixed roots (`SummaryModal`, `UserProfileModal`) renamed. Every component now uses `.component.tsx` (pages `.page.tsx`) except `navbar/Navbar.tsx`. Rule for new modals: own folder; import another modal's files only via `shared/`, never across sibling folders.
- [ ] Import style: absolute `src/...` alias and relative `../` imports are mixed within the same files (e.g. `movie.service.ts`/`tv.service.ts` import their detail models via relative paths like `'../models/movieDetails.model'`, while `AppContext.tsx`/`types.ts` import the same kind of model via the absolute `src/...` alias). Still true in `movie.service.ts`, `tv.service.ts`, `tmdbList.service.ts`, `watchList.service.ts`. New code in `modal/` uses `src/...` for anything outside its own folder.
- [ ] Naming for "Tv": `TvShow`/`TvService` (services) vs `TVShowDetails` (models) — two casings for the same abbreviation.
- [ ] Three different type-suffix conventions coexist: `.model.ts`, inline types in `.service.ts`, and `.type.ts` (just for `RoutePaths`).
- [ ] `tsconfig.json` looks like a leftover full config that predates the `tsconfig.app.json`/`tsconfig.node.json` split — it has no `references` field tying the split together, which is the standard pattern once configs are split like that. **Now actively broken**: TypeScript ~7.0 removed `baseUrl` and `moduleResolution: "node"`, both still in `tsconfig.json`, so `npm run typecheck` fails on the config (TS5102/TS5108) before checking any code, and `npm run build` (plain `vite build`) never type-checks. Fix: drop `baseUrl`, add `"paths": { "*": ["./*"] }`, switch to `"moduleResolution": "bundler"` (as `tsconfig.app.json` already does), and consider `tsc -b && vite build`. CLAUDE.md documents the throwaway-config workaround and the known baseline errors until then.

## 🔐 Auth & watch-list follow-ups

- [ ] **Terms/Privacy links bypass the router.** `UserAuthSignUpTab` uses `<Link href='/terms'>` / `'/privacy'` — plain hrefs ignore the `/StreamLens/` basename (they'd leave the app on GitHub Pages), and neither route exists. Add the routes and use `component={RouterLink} to=...`.
- [ ] **Terms sentence is concatenated from fragments** (`agreeToTermsPrefix` + link + `and` + link + "."), which fixes English word order into fr/ar. Use i18next `<Trans>` with one key containing both links.
- [x] **"Continue as guest"** in `UserAuthModal` has no `onClick` (it should at least close the modal).
- [x] **`CLEAR_SESSION` has no callers and doesn't sign out of Firebase.** Sign-out currently happens via `signOut(auth)` in the profile modal, with the listener clearing `user`. Either remove `clearSession` or make it the one sign-out path (`signOut` + storage + query cache). **Removed** (action, reducer case, context function and type). A dedicated sign-out path would only cover the button that calls it, while revoked/expired sessions, account deletion and sign-out in another tab bypass app code entirely — all of them reach `onAuthStateChanged(null)`, so that's where cleanup now lives. Its behavior was also wrong for the app: `localStorage.clear()` wiped the theme preference (and would wipe Firebase's own storage if it had fallen back from IndexedDB), and resetting `snackBarProps` would cancel a "signed out" message.
- [x] **Query cache isn't cleared on sign-out.** Watch-list keys are scoped by uid, so nothing leaks between accounts, but the previous user's data stays in memory. **Fixed**: the auth listener in `AppContextProvider` calls `queryClient.removeQueries({ queryKey: [WATCH_LIST_QUERY_ROOT] })` when the user becomes `null`. TMDB caches are kept (not per-user). New user-scoped queries should export a key root the same way and be added there.
- [ ] **Watch list has no consumers or mutations yet.** When writes land: `useMutation` + `invalidateQueries({ queryKey: [WATCH_LIST_QUERY_ROOT, uid] })` (root exported from `useWatchList.ts`; sign-out already drops those queries). Storage is one document per user (`watchLists/{uid}`, the `WatchList` model stored as-is), so each write rewrites the whole `watch_list` array and must go through `runTransaction` to avoid losing a concurrent edit from another tab. `setMovieWatched`, `setEpisodeWatched` and `removeEntry` now exist (each a `runTransaction` read-modify-write that skips the write when nothing changed); still missing are the `useMutation` hooks and any UI calling them, and none of it has run against a real Firestore yet.
- [x] **Firestore security rules weren't in the repo** — the database was governed only by whatever the console had (test mode opens it to everyone until it expires, then denies everything). **Added** `firestore.rules` (owner-only `watchLists/{uid}`, everything else denied) plus `firebase.json`; deploy with `npx firebase deploy --only firestore:rules`. Not yet verified against the emulator.
- [ ] **No tests** exist for any of this (or anything else) — see CLAUDE.md for the missing Vitest setup.
